# Setup Guide

This guide will help you get the Anvara Take-Home Test running on your machine.

## Prerequisites

Before you begin, make sure you have:

- **Node.js 22.13+ (22.x) or 24+** - [Download](https://nodejs.org/)
- **pnpm 11.21.0** - Installed via npm or corepack
- **Docker Desktop** - [Download](https://www.docker.com/products/docker-desktop/)

### Install pnpm

If you don't have pnpm installed:

```bash
npm install -g pnpm@11.21.0
```

## Platform Support

This project works on:

- ✅ **macOS** (Intel and Apple Silicon)
- ✅ **Windows** (10/11 via PowerShell, CMD, or Git Bash)
- ✅ **Linux** (Ubuntu, Debian, Fedora, etc.)

All scripts use cross-platform tools to ensure compatibility.

## Quick Setup (Recommended)

Run the automated setup script:

```bash
pnpm install --frozen-lockfile
pnpm setup-project
```

**Use a disposable local database.** Setup seeds demo accounts and deletes existing
authentication and application data in the configured database. `pnpm reset` also
removes Docker volumes. Neither command is needed for ordinary development.

This will:

1. ✅ Check prerequisites (Node.js, pnpm, Docker)
2. ✅ Copy `.env.example` to `.env`
3. ✅ Install all dependencies
4. ✅ Start Docker containers (PostgreSQL on port 5498)
5. ✅ Generate Prisma client
6. ✅ Apply database schema
7. ✅ Seed the database with sample data

## Manual Setup

If you prefer step-by-step setup:

### 1. Install Dependencies

```bash
pnpm install --frozen-lockfile
```

### 2. Configure Environment

```bash
# Unix/Mac
cp .env.example .env

# Windows (Command Prompt)
copy .env.example .env

# Windows (PowerShell)
Copy-Item .env.example .env
```

Generate a secret with `openssl rand -hex 32` and set `BETTER_AUTH_SECRET` in `.env`.
Keep `.env` untracked. The example database URL matches the Docker defaults.

### 3. Start Database

```bash
docker compose up -d
```

### 4. Setup Prisma

```bash
pnpm --filter @anvara/backend db:generate
pnpm --filter @anvara/backend db:push
pnpm --filter @anvara/backend db:seed
```

The seed creates Better Auth tables and both demo accounts as well as application
data. It replaces existing data; run it only on a disposable database.

## Environment Variables

The `.env` file contains all necessary configuration:

```bash
# Database (auto-generated with random credentials)
DATABASE_URL=postgresql://postgres:<password>@localhost:5498/<db_name>

# Backend API
BACKEND_PORT=4291
NEXT_PUBLIC_API_URL=http://localhost:4291

# Authentication (Better Auth)
BETTER_AUTH_SECRET=<auto-generated>
BETTER_AUTH_URL=http://localhost:3847
```

> **Note:** The setup script generates unique credentials automatically.

### 🎯 Pro Tip: Use Prisma Studio

Prisma Studio is a visual database browser that makes debugging **much easier**:

```bash
pnpm --filter @anvara/backend db:studio
```

Opens at http://localhost:5555. Use it to:

- ✅ **Verify seeded data** - See the demo sponsors, publishers, campaigns, and ad slots
- ✅ **Debug CRUD operations** - Check if your create/update/delete actually worked
- ✅ **Inspect relationships** - View how sponsors, campaigns, and other models connect
- ✅ **Test edge cases** - Manually modify data to test your error handling

This is incredibly helpful when working on Challenges 3-5!

## Production preview and verification

After setup, run from the repository root:

```bash
pnpm typecheck
pnpm lint
pnpm test --run
pnpm build
pnpm --parallel --filter @anvara/backend --filter @anvara/frontend start
```

Both build and start scripts load the root `.env`; environment variables supplied by
the calling shell take precedence. For development, use `pnpm dev` instead of the
production start command. Do not run both on the same ports.

For the browser suite, leave either stack running, install the browsers once with
`pnpm exec playwright install chromium webkit`, then run `pnpm e2e` in another terminal.
The suite uses both demo accounts and creates uniquely named records that it removes
afterward. It does not reset or seed the database.

## Troubleshooting

### Docker Issues

```bash
# Check if Docker is running
docker ps

# Restart Docker containers
docker compose down
docker compose up -d
```

### Database Issues

```bash
# Reset database
cd apps/backend
pnpm db:push --force-reset
pnpm db:seed
```

### Port Conflicts

If ports 3847, 4291, or 5498 are already in use, update the `.env` file:

```bash
BACKEND_PORT=4292  # Change to available port
# Update NEXT_PUBLIC_API_URL accordingly
```

### pnpm Issues

```bash
# Clear pnpm cache
pnpm store prune

# Reinstall dependencies
rm -rf node_modules
pnpm install --frozen-lockfile
```
